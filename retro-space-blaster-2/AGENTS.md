# Agent guide — Retro Space Blaster

Instructions for AI coding assistants (Claude Code, Cursor, Codex, Copilot).
Humans: see README.md.

This is a **Devvit Web** app (Reddit's developer platform). The game is
**vanilla JavaScript** — do not introduce React, Tailwind, or a framework.

## Layout

- `src/client/game/` — the game (plain JS ES modules, 4-space indent, not Prettier-formatted)
- `src/client/splash.*` — lightweight feed card. Keep it small: no game imports.
- `src/server/` — Hono API on Devvit; `redis`, `reddit`, `context` from `@devvit/web/server`
- `src/shared/` — types + pure validation used by both sides (unit tested)
- `art/sprites/` — master art. `public/assets/sprites/` is GENERATED by `npm run art` — never edit it.

## Rules

- Webview code must not call third-party URLs (Reddit blocks them). Bundle assets instead.
- Webview may only call this app's own `/api/*` routes.
- Every server route validates input with `src/shared/validation.ts` before touching Redis.
- New Redis keys go in `src/server/core/keys.ts`.
- New saved settings: update `SYNCED_KEYS` (game/store.js) AND `SAVE_KEYS` (shared/validation.ts).
- Use `navigateTo` / `showToast` from `@devvit/web/client` instead of `window.location` / `alert`.
- No inline `<script>` tags in HTML.
- TypeScript: type aliases over interfaces, named exports, no `as` casts.
- Never use `@devvit/public-api` or Blocks — this project is Devvit Web only.
- Menu items / triggers need both a route AND an entry in `devvit.json`.
- Comment new code with the _why_, plus a short real-world analogy for non-obvious pieces (project owner's preference).

## Commands

- `npm run check` — types + lint + format + unit tests (must pass before commit)
- `npm run build` — art pipeline + Vite client/server build
- `npm run local` — browser preview, no Reddit
- `npm run dev` — live playtest on Reddit (needs `devvit login`)
